# 视频去重算法

## 检测流程

`scan`、`report` 和 `dedupe` 共用 `DeduplicationEngine.analyze()`。
检测阶段只读文件，不从未实现的缓存或 LSH 索引获取结果。

1. 根据扫描配置收集视频，保留每个文件的独立 ID、路径及文件状态签名。
2. 按文件大小建立候选桶，对存在多个文件的桶计算完整 SHA-256。
   摘要非空、文件大小一致且计算前后文件状态一致，才能证明精确重复。
3. 每个精确重复组只提取一份指纹，单文件也提取指纹。
4. 对完整可读的视频进行时长过滤及有序画面比较。
5. 根据保留评分选择中心，只合并直接匹配中心的文件，最终展开精确重复组的成员。

## 指纹版本与采样

当前指纹版本为 2；旧指纹必须重新提取，不能与当前指纹直接比较。
默认均匀采样包含首尾并覆盖全片，配置默认值以 `config.py` 为准。
每个采样点记录目标帧、实际帧、时间、归一化位置及读取状态。
定位偏差超过一帧或读取失败属于异常，不会悄悄丢弃后当作完整指纹。
成功帧缩小后立即保存，限制高分辨率视频的内存开销。

场景采样是可选的有界粗采样：保留均匀覆盖的锚点，补入场景变化点，
所有最终采样位置排序、去重且总数不超过配置帧数；不全量保存场景帧。

pHash 使用 `hash_size * 4` 尺寸进行 DCT，采用除 DC 外的低频系数中位数。
pHash、dHash、aHash 均输出 `hash_size ** 2` 位，十六进制末端表示需要的填充位不计入 DTW 分母。

## 内容判定

汉明距离是两个十六进制值转为整数后异或的置位数。
DTW 对齐按帧时间顺序进行，只允许归一化时间位置差不超过 0.1 的帧对。

```
帧相似度 = 1 - 汉明距离 / 指纹实际位数
序列相似度 = 对齐路径上帧相似度的平均值
匹配覆盖率 = min(两侧各自达标的不同帧数量 / 各自采样帧数)
```

自动内容去重要求同时满足：时长差占较长视频比例不超过配置容差，
序列相似度达到配置阈值，两侧匹配覆盖率达到配置要求。
不以视频文件大小、分辨率或容器不同排除内容副本。
感知相似只证明画面匹配，不等同于完整文件摘要一致；音轨不参与判定。

## 待确认与执行

字节不同且采样不完整的视频只提供邻近时间点的可读部分匹配证据，
报告采样失败、候选路径、相似度和覆盖率，不进入自动操作清单。
完全相同的字节副本可以独立依赖摘要证据去重，即使不能解码。

完整文件保留沿用分辨率、大小、名称和修改时间评分，同分按规范化路径稳定选择。
内容分组的每个成员必须直接与最终保留文件达标，避免链式误合并。
文件在分析期间变化、读取失败或执行前签名不一致时，记录失败并保留文件。

`scan`、`report` 永远只读。`dedupe` 默认只报告且模拟运行；
指定 `--action move/delete/link --no-dry-run` 才实际处理。
报告区分计划、模拟、成功、失败和跳过，并始终列出待确认与失败明细。
操作或读取失败返回退出码 1；仅有待确认项返回 0，须查看报告。

数据库仅保存可用的字段和指纹版本，新字段为增量扩展；CLI 不读取缓存结果。
